# 11. 라이브 이벤트 맵 (Live Event Map) — 기획서 v1.0

> 상태: **P1 구현 완료** (v1.67~1.69, 2026-06). 관리자 등록 풀세트 — 등록·홈피드·지도·좋아요/저장/조회까지 라이브.
> 목표: 정적 장소 분류(POI: 일반/음식/카페)를 넘어 **"지금 어디서 무슨 일이 벌어지는가"** 를 보여주는 실시간 이벤트 맵으로 확장.

## ✅ P1 구현 완료 (요약)
- **데이터**: `events` 컬렉션 + `PinEvent` 모델(`lib/models/event.dart`), `cleanupEndedEvents`(매시간 종료 자동숨김).
- **권한**: `events` 읽기 공개 / 쓰기 마스터(`isMaster`). 좋아요·저장·조회 카운트는 일반 사용자 허용(diff 제한). 포스터는 Storage `events/` 마스터 업로드.
- **등록**: 마스터 전용 `event_edit_screen` / `event_admin_screen` (프로필 → 🎪 이벤트 관리).
- **홈 피드**: 2번째 줄 칩을 이벤트 카테고리로 전환. 전체=이벤트+일상, 카테고리=해당 이벤트, 🍿일상=친구 피드. `EventCard`.
- **친구지도**: [친구 | 이벤트] 모드 토글 + 이벤트 마커 + 카테고리/반경(3·10·30km·전국) 필터, 탭→상세(EventCard).
- **참여**: 좋아요/저장(서브컬렉션 + 카운터)/조회수(세션당 1회).
- **P2 이후**: 크롤러(자동수집), 타깃 취향 필터, geohash viewport 쿼리·클러스터링, 관심 이벤트 알림.

---

## 1. 비전 / 한 줄 컨셉

- 기존: 사용자가 남긴 **과거형** 기록(브이로그·체크인) 중심.
- 추가: **현재~미래형** 이벤트(행사/공연/축제/혜택) 중심의 "라이브 이벤트 맵".
- 핵심 차별점: 모든 핀에 **시작~종료 일시**가 있고, **끝난 이벤트는 자동으로 사라진다** → 유저가 헛걸음하지 않음.

## 2. 5대 이벤트 카테고리

2번째 라인 필터를 POI → **이벤트 카테고리**로 전환.

```
[전체] [🏆 스포츠/레저] [🎭 공연/전시] [🎪 축제/바자회] [🏢 기업/브랜드] [🎓 교육/클래스] [🍿 일상]
```

| 코드값 | 라벨(구현) | 이모지 | 설명 | 주 데이터 출처 |
|--------|------|--------|------|----------------|
| `sports` | 스포츠/레저 | 🏆 | KBO·K리그, 마라톤, 지역 대회, 동호회 매치 | 티켓링크/인터파크, 지역 체육회, 네이버 스포츠 |
| `culture` | 공연/전시 | 🎭 | 연극·뮤지컬, 특별전시, 팝업스토어, 북콘서트 | 서울시 문화행사 API, 공연장 일정 |
| `festival` | 축제/바자회 | 🎪 | 구청 축제, 플리마켓, 전통시장 야시장, 단지 장터 | 지자체 소식지, 문체부 축제데이터, SNS 해시태그 |
| `public` | 기업/브랜드 | 🏢 | 기업 행사·브랜드 팝업스토어, 신제품 체험, 채용·취업박람회 | 기업 채널, 팝업 큐레이션 |
| `education` | 교육/클래스 | 🎓 | 원데이클래스, 세미나·강연, 워크숍, 무료강좌, 어린이 체험 | 공공서비스예약, 클래스 플랫폼 |
| `daily` | 일상 (UGC) | 🍿 | 유저 체크인·맛집·카공·번개 — **기존 사용자 콘텐츠** | 핀플릭 UGC (vlogs/check-ins) |

> 지자체 주최 행사는 성격에 맞춰 공연/전시·축제/바자회·교육/클래스로 흡수(별도 칸 없음).

> 🍿 **일상**은 기존 유저 콘텐츠가 이벤트 더미에 묻히지 않게 보호하는 장치. 별도 수집 없이 기존 `vlogs`를 그대로 매핑.

## 3. 메타 태그 (AI 필터링용)

5대 카테고리에 더해, 등록(관리자/크롤러) 시 자동 부여하는 메타 태그.

| 태그 | 값 | 용도 |
|------|----|------|
| **기간** `periodType` | `oneoff`(단발성: 콘서트·마라톤) / `ongoing`(상시·장기: 3개월 전시) | "오늘만/이번주" 필터 정교화 |
| **비용** `costType` | `free` 🎁 / `paid` 🎫 | **"무료만 보기"** 토글 |
| **타깃** `audience[]` | `all`/`kids`/`2030`/`family`/`senior` 등 | 취향 필터 (Phase 2) |

## 4. 데이터 모델 (제안)

### 핵심 결정 — 별도 `events` 컬렉션 신설 (권장)
이벤트는 ① 라이프사이클(시작/종료), ② 출처(관리자·크롤러·UGC), ③ 정렬 기준(과거형 createdAt이 아니라 startAt/endAt)이 기존 `vlogs`와 달라, **별도 컬렉션**이 깔끔합니다.
🍿 일상은 기존 `vlogs`를 그대로 쓰고, **이벤트 맵은 `events` + `vlogs`(daily) 두 소스를 합쳐서** 보여줍니다.

```
events/{eventId}
  title          string                  // 행사명
  category       'sports'|'culture'|'festival'|'public'   // (daily는 vlogs)
  description    string
  posterUrl      string?                 // 포스터/대표 이미지
  thumbnailUrl   string?
  lat, lng       number                  // 위치
  placeName      string                  // 장소명(경기장/공연장/공원 등)
  address        string?
  startAt        timestamp  ★필수         // 시작 일시
  endAt          timestamp  ★필수         // 종료 일시
  allDay         bool                    // 종일/기간형 여부
  periodType     'oneoff'|'ongoing'
  costType       'free'|'paid'
  price          string?                 // 표시용("성인 15,000원")
  audience       array<string>           // 타깃층
  link           string?                 // 예매/상세 링크
  source         'admin'|'crawler'       // 등록 출처
  sourceName     string?                 // "서울 열린데이터" 등
  externalId     string?                 // 크롤러 중복 방지 키(출처+원본ID)
  status         'active'|'ended'|'hidden'
  createdBy      uid?                    // 등록 관리자
  viewCount/likeCount/saveCount  number
  createdAt/updatedAt  timestamp
```

### 라이프사이클 — "종료 이벤트 자동 숨김" (삭제 X, 보존 O)
- **표시 조건**: `status == 'active'` && `endAt >= now`.
- **스케줄러**(Cloud Functions, 매시간/매일): `endAt < now` 인 active → `status = 'ended'` 로 전환(삭제하지 않고 **보존** — 재개최·통계·히스토리용).
- **클라이언트도 `endAt` 기준 필터** 병행(스케줄러 지연 보완) — 기존 체크인 만료와 동일 패턴.
- 인덱스: `events` (category ASC, status ASC, startAt ASC) / (status ASC, endAt ASC).

## 5. 화면 / UX

### (1) 카테고리 필터 탭 (2번째 라인)
- `[전체][🏆][🎭][🎪][🏛️][🍿]` 가로 스크롤 칩.
- 추가 필터: **`무료만 🎁`** 토글, **기간**(오늘 / 이번 주 / 진행 중).

### (2) 이벤트 카드 (피드)
```
┌──────────────────────────────┐
│ [포스터 이미지]   🟢 진행중      │  ← 상태 배지(D-3 시작 / 진행중 / 오늘 종료)
│ 🎭 공연·전시   🎫 유료          │  ← 카테고리칩 + 비용칩
│ 행사명(굵게)                    │
│ 📅 6/10(화) 19:30 ~ 6/15(일)    │  ← 시작~종료 일시 ★
│ 📍 세종문화회관 · 종로구         │
│ [예매/상세 보기 ↗]   ♥  🔖  👁  │
└──────────────────────────────┘
```
> 기존 '방금 전/1일 전' 과거형 타임스탬프 대신 **일정/상태 배지**가 핵심.

### (3) 지도 마커
- 카테고리별 색/이모지 마커(🏆🎭🎪🏛️). 일상(🍿)은 기존 UGC 마커.
- "오늘 종료/마감 임박" 강조 배지.
- 마커 탭 → 이벤트 상세 시트(일정·장소·링크·지도길찾기).

## 6. 등록 흐름 (단계적)

### Phase 1 — 관리자 수동 등록 (시작점)
- **마스터 계정(현 `isMaster`: jaduck9)** 전용 이벤트 등록/수정 화면.
- Firestore `events` 직접 작성. 규칙: `read: all`, `write: master`(+ 추후 크롤러 서비스 계정).
- 카테고리·일시·비용·링크·포스터 입력. 위치는 기존 `MapPickerSheet` 재사용.

### Phase 2 — AI 크롤링 에이전트 자동 등록
- 외부 에이전트(Cloud Functions 스케줄 또는 별도 스크립트 + Admin SDK)가 공개 API 수집 → `events` **upsert(externalId 중복 제거)**.
- 출처별 파서: 서울 열린데이터광장(문화행사 API), 공공서비스예약, 축제데이터 등.
- 메타 태그(기간/비용/타깃) 자동 부여, 위치 지오코딩, 품질/중복 관리.

## 8. 확정이 필요한 결정 (대표님 콜)

1. **진입점/네비게이션**
   - (A) 기존 **홈 피드의 2번째 라인 필터**를 이벤트 카테고리로 전환 (현 구조 유지) — 또는
   - (B) 하단탭에 **별도 '이벤트' 탭 신설**(현 5탭: 홈/친구지도/➕/갤러리/친구) — 또는
   - (C) **친구지도**를 "친구 + 이벤트" 통합 지도로 확장.

2. **데이터 구조**: 별도 `events` 컬렉션(권장) vs 기존 `vlogs` 확장.

3. **종료 이벤트**: 숨김 보존(권장) vs 완전 삭제.

4. **P1 범위 확정**: 관리자 등록 + 필터 + 마커 + 자동숨김까지를 1차 구현으로?

5. **마스터 권한 운영**: 관리자 등록을 jaduck9 단일 마스터로 시작 vs 별도 `role: admin` 필드 도입.
